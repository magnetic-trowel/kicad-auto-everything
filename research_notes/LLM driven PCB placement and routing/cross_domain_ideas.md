## Q1. LLM-driven layout generation in other fields (graphic/UI, 3D indoor scenes, floorplans, CAD code): which use "LLM emits relational constraints → optimizer solves geometry", and how well does it work?

### Takeaway
Many systems now follow the same pattern: the LLM proposes semantic structure (relations, a scene graph, or a program) and a solver handles the geometry. Holodeck, LayoutVLM, the Brown "open-universe" layout-language system, SceneCraft, I-Design and RoomCraft all work this way. The strongest results come from hybrids. LayoutVLM has the model output both numeric initial poses and differentiable relations, which beat pure-LLM and pure-constraint baselines. Brown's 2025 follow-ups found that an imperative placement program, repaired by an LLM-free parameter search, was preferred 82% and 94% of the time over two declarative constraint-solver methods. So "LLM writes constraints, solver does geometry" works, but it is not clearly the best design. "LLM writes relative-placement code, then a numeric search repairs it" is a strong competitor.

### Cited Findings
**Graphic/UI layout (LLM as layout writer)**
- **LayoutGPT** (NeurIPS 2023; code public) serializes layouts as CSS. Each category name is a selector, and position and size become CSS declarations. Values are normalized to a maximum of 256px, and prompts carry in-context exemplars. The authors argue that code-trained LLMs read spatial meaning better from CSS than from a bare number sequence. They report 20–40% gains in numerical and spatial correctness over text-to-image systems, and results comparable to supervised methods on 3D indoor scene synthesis. — [arXiv 2305.15393](https://arxiv.org/pdf/2305.15393); [NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2023/hash/3a7f9e485845dac27423375c934cb4db-Abstract.html)
- **LayoutPrompter** (NeurIPS 2023; Microsoft LayoutGeneration repo) needs no training. It uses in-context learning with three parts: input-output serialization, dynamic exemplar selection, and a layout ranker that picks the best of several LLM samples. It matches or beats trained SOTA and is "significantly superior" to a training-based baseline when data is scarce. — [NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2023/hash/88a129e44f25a571ae8b838057c46855-Abstract.html); [arXiv 2311.06495](https://arxiv.org/abs/2311.06495v1)
- **LayoutNUWA** (ICLR 2024; code in the ProjectNUWA GitHub) uses "Code Instruct Tuning". Layout conditions become HTML with masked slots, an LLM fills the masks, and the result is rendered. The authors claim more than 50% improvement over prior work on several datasets, and argue that numeric-only formulations miss semantic relations. — [ICLR proceedings](https://proceedings.iclr.cc/paper_files/paper/2024/hash/a6a1e4c756d700d9aedcc1896a7e6fb0-Abstract-Conference.html); [arXiv 2309.09506](https://arxiv.org/abs/2309.09506v1)

**3D indoor scene layout (LLM proposes relations, solver places)**
- **Holodeck** (CVPR 2024; [code](https://github.com/allenai/Holodeck)): GPT-4 generates spatial relational constraints between objects, and a layout step is then optimized to satisfy them. Assets come from Objaverse (more than 50K). Annotators preferred its residential scenes over procedural baselines. — [arXiv 2312.09067](https://arxiv.org/pdf/2312.09067); [CVPR paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Yang_Holodeck_Language_Guided_Generation_of_3D_Embodied_AI_Environments_CVPR_2024_paper.pdf)
  - Constraint vocabulary: global (edge, middle), distance (near, far), position (in front of, side of), alignment (center-aligned) and rotation (face to). Example: a coffee table gets [middle, in front of(sofa), face to(sofa), near(sofa)]. Relational constraints are soft; collisions and room boundaries are hard. — [arXiv 2312.09067](https://arxiv.org/pdf/2312.09067); [CVPR supplement](https://openaccess.thecvf.com/content/CVPR2024/supplemental/Yang_Holodeck_Language_Guided_CVPR_2024_supplemental.pdf)
  - Solver: each object has a center, width, depth and one of four rotations. A grid makes the space discrete, the **anchor object is placed first**, and depth-first search (DFS) places the rest while keeping as many soft constraints as possible. A MILP solver also exists, but the README says "to yield better layouts, use DFS". — [arXiv 2312.09067](https://arxiv.org/pdf/2312.09067); [GitHub](https://github.com/allenai/Holodeck)
  - Holodeck 2.0 turns each parsed statement into a typed constraint (type, relation, source, target). Left-of and right-of become planar ordering along an axis relative to the target's bounding box, with a 0.1 m buffer. Its pseudocode gives the DFS solver timeout and node limits. — [arXiv 2508.05899](https://arxiv.org/pdf/2508.05899)
  - Critique: grid DFS limits solutions to discrete candidates and can produce layouts that are physically valid but semantically inconsistent. — [R3L, arXiv 2605.06758](https://arxiv.org/pdf/2605.06758)
- **LayoutVLM** (CVPR 2025, Stanford/Google; project page) uses a hybrid representation. A VLM looks at **visually marked images** and outputs both **numerical pose estimates** (initial positions and orientations) and **differentiable spatial relations**, which are then optimized jointly. Self-consistent decoding improves the VLM's spatial planning. Results are more physically plausible and better aligned with instructions than "existing LLM and constraint-based approaches". Fine-tuning a VLM on this representation, extracted from existing scene datasets, improved its reasoning. — [project page](https://ai.stanford.edu/~sunfanyun/layoutvlm/); [arXiv 2412.02193](https://arxiv.org/html/2412.02193v3); [CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Sun_LayoutVLM_Differentiable_Optimization_of_3D_Layout_via_Vision-Language_Models_CVPR_2025_paper.html)
- **Open-Universe Indoor Scene Generation** (Brown, 2024): the LLM writes programs in a **domain-specific layout language** that describe objects and their spatial relations. Running the program yields a constraint satisfaction problem, which **gradient-based optimization** solves for positions and orientations. A VLM retrieves meshes from unannotated databases. It beat generative models trained on 3D data (closed-universe) and an LLM-based layout method (open-universe). — [arXiv 2403.09675](https://arxiv.org/pdf/2403.09675)
- **Imperative vs. declarative** (Brown follow-ups, 2025): this work compares the declarative approach (LLM writes constraints for a solver) with an imperative one (LLM writes a step-by-step program that places each object relative to earlier ones). Its error correction changes one parameter at a time so the program stays close to the original. Claude 3.5 Sonnet's layouts were "most amenable to correction" and had the fewest errors after correction. A noted weakness: once an object is placed imperatively it cannot be moved. — [arXiv 2504.05482](https://arxiv.org/pdf/2504.05482)
- **Procedural Scene Programs / LLM-free error correction via program search** (SIGGRAPH Asia 2025, with Daniel Ritchie as co-author): an imperative layout method whose error correction works directly on the generated code with no further LLM calls. In forced-choice studies, people preferred its layouts over two declarative methods **82% and 94%** of the time. — [arXiv 2510.16147](https://arxiv.org/html/2510.16147v1)
- **SceneCraft** (Hu et al., Google, ICML 2024 oral): text becomes Blender Python for scenes with up to about 100 assets. The pipeline builds a scene graph as a blueprint, turns relations into numerical constraints, and refines iteratively while a VLM (GPT-V) critiques renders. **Library learning** collects common script functions into a reusable library, so the agent improves without any weight updates. It beats other LLM agents on constraint adherence and in human ratings. — [PMLR](https://proceedings.mlr.press/v235/hu24g.html); [mlanthology](https://mlanthology.org/icml/2024/hu2024icml-scenecraft); [alphaXiv](https://alphaxiv.org/abs/2403.01248)
- Not to be confused with **SceneCraft** (NeurIPS 2024, layout-guided), which conditions a diffusion/NeRF pipeline on user-drawn bounding boxes and has no LLM constraints. — [Illinois Experts](https://experts.illinois.edu/en/publications/scenecraft-layout-guided-3d-scene-generation/)
- **RoomCraft** (2025): extracts room type, furniture and spatial relations, uses a **heuristic DFS to order placement**, then runs constraint-driven optimization to avoid collisions. — [arXiv 2506.22291](https://arxiv.org/pdf/2506.22291)
- **I-Design** (ECCV workshops 2024): LLM agents reason in dialogue to produce a scene graph, and a placement algorithm then picks locations. A third-party review says one agent checks for out-of-bounds objects and implausible connections; I could not confirm this in the paper. — [mlanthology](https://mlanthology.org/eccvw/2024/celen2024eccvw-idesign); [Moonlight review](https://www.themoonlight.io/review/i-design-personalized-llm-interior-designer)
- **LLplace** (2024): a fine-tuned Llama 3 outputs the layout directly from room type and object list, with no spatial priors or in-context exemplars. It is trained on a 3D-Front dialogue dataset that supports adding and removing objects. — [HF papers 2406.03866](https://huggingface.co/papers/2406.03866)
- **INTERIORAGENT** is reported as an LLM-agent framework that encodes design principles in a scene description language and enforces constraints iteratively with optimization tools (search snippet only). — [UCSD/Brown related PDF](https://cseweb.ucsd.edu/~ravir/kunal_3dv.pdf)

**Architectural floorplans**
- **House-GAN** (ECCV 2020): a graph-constrained relational GAN. Input is a bubble graph of room types and adjacency; output is axis-aligned room boxes. Trained and evaluated on 117,000 floorplans. — [arXiv 2003.06988](https://arxiv.org/abs/2003.06988)
- **Graph2Plan** retrieves a graph layout from a dataset and generates room boxes "in an ad-hoc way", and needs complex post-processing to produce vector plans (per a later paper's related-work section). — [arXiv 2408.16258](https://arxiv.org/pdf/2408.16258v1)
- **HouseDiffusion** (CVPR 2023): a Transformer diffusion model whose **attention masks are derived from the input graph**. Nodes are rooms and edges are doors. It outputs vector floorplans directly with no post-processing, can produce non-Manhattan shapes, and is evaluated on RPLAN. — [arXiv 2211.13287](https://arxiv.org/abs/2211.13287v1); [ar5iv](https://ar5iv.labs.arxiv.org/html/2211.13287)
- **HouseTune / HouseLLM** (2024–25): an LLM uses chain-of-thought to draft a layout, then a conditional diffusion model refines it to satisfy physical and user constraints. The stated motivation is that LLM output alone "lacks precise geometry" and that floorplan datasets are scarce. — [arXiv 2411.12279](https://arxiv.org/abs/2411.12279v4)
- **RL-tuned LLM floorplanning** (Lara et al., ACL Findings 2026): an LLM fine-tuned on real plans, then trained with **RL from verifiable rewards** for topological and numeric constraints (room sizes, areas) while penalizing overlap. It reports at least a 94% relative reduction in "Compatibility" error. Source found only via an ACL Anthology author page. — [ACL Anthology author page](https://aclanthology.org/people/luis-lara/)
- **Text-to-Layout for BIM** (2025): produces Revit-native parametric floor plans for professional BIM workflows. — [arXiv 2509.00543](https://arxiv.org/abs/2509.00543v1)

**CAD code generation**
- **Text-to-CadQuery** (2025): LLMs write CadQuery Python directly. The authors added 170K CadQuery annotations to Text2CAD and fine-tuned six open models. Best top-1 exact match went from 58.8% to 69.3%, and Chamfer Distance fell 48.6%. — [HF papers 2505.06507](https://huggingface.co/papers/2505.06507)
- **CAD-Coder** (NeurIPS 2025): supervised fine-tuning, then **GRPO reinforcement learning with a Chamfer-Distance geometric reward** plus a format reward, chain-of-thought planning, and 110K text–CadQuery–3D triplets. Mean CD is 6.54 (×10⁻³) versus 29.29 for Text2CAD. A key advantage: the scripts can be executed to check validity. — [NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2025/hash/564a224e88f2490f3c1deaae877d37e3-Abstract-Conference.html); [alphaXiv](https://alphaxiv.org/abs/2505.19713)

### Inferences
- **Overall verdict on "LLM emits constraints → solver".** It works when (a) the constraint vocabulary is small and typed (Holodeck: about five relation families), (b) relations are soft while collisions and boundaries are hard, and (c) the solver is continuous or differentiable, or seeded with numeric initial poses (LayoutVLM, open-universe). Pure discrete grid DFS gives valid but semantically odd layouts (R3L critique). Pure LLM coordinates lack geometric precision (HouseTune, Lara). The imperative-program result (82%/94% preference) is the strongest warning that a declarative solver can wash out what the LLM intended. A PCB system should support both modes and compare them on its own benchmark.
- **Transfer to PCB — typed relational constraint DSL (Holodeck/Holodeck 2.0).** Define a small PCB vocabulary that maps one-to-one onto the Holodeck families:
  - *global*: `edge(J1, side=W)`, `middle(U1)`
  - *distance*: `near(C12, U1.pin[VDD3], max=1.5mm)`, `far(L1, U5, min=8mm)`
  - *position*: `left_of(U2, U3)`, `same_side(C*, U1)`
  - *alignment*: `align_row([R1..R8], axis=x, pitch=2.0mm)`
  - *rotation*: `face(U2.pin1, toward=U1)`, `orient(J2, opening=outward)`

  Mark DSL constraints as soft with weights. Hard constraints come from KiCad: courtyard non-overlap, board outline, keepout zones and mounting holes. Copy the anchor-first ordering: place connectors, mounting holes and the MCU/SoC first, then DFS or CP-SAT for the rest. Holodeck 2.0's typed tuple `(type, relation, source, target, buffer)` is a ready JSON schema for LLM tool calls.
- **Transfer to PCB — LayoutVLM hybrid.** Have the LLM/VLM output *both* approximate (x, y, θ) for each footprint *and* differentiable relations. Then run a DREAMPlace-style gradient optimizer. Its loss would combine HPWL, a smooth courtyard-overlap density, relation penalties, and staying close to the LLM's poses. The VLM input should be a rendered board image with set-of-mark labels (reference designators drawn on footprints). Self-consistent decoding means sampling several layouts and keeping the relations the samples agree on. The "fine-tune on representation extracted from datasets" result suggests mining relations (near, align, edge) from open-source KiCad boards to fine-tune an open model.
- **Transfer to PCB — imperative placement programs plus LLM-free program search (Brown 2025).** Give the LLM a Python API of relative operations, such as `place(C5, right_of=U1.pin(12), gap=0.4)`, `ring(decaps, around=U1)` and `row(R1..R8, below=U3, pitch=2)`. Then treat every numeric literal in the generated program as a search variable. A local search (coordinate descent, CMA-ES or CP-SAT over discretized gaps) fixes courtyard and DRC violations and ratsnest crossings without more LLM calls. This keeps the program close to the LLM's intent, which is the stated reason for one-parameter-at-a-time correction. It is cheap and should probably be the default baseline.
- **Transfer to PCB — SceneCraft-style VLM critique and library learning.** Render each iteration from KiCad (pcbnew's Python API or `kicad-cli pcb export svg`), ask a VLM to critique it ("decoupling caps for U3 are on the far side of the via field"), and patch the code. Keep a **growing library of verified placement macros**, for example "QFN decoupling ring", "buck converter hot-loop compact", "USB-C connector + ESD + CC resistors" and "crystal + load caps near MCU". This is SceneCraft's library learning applied to recurring PCB subcircuits.
- **Transfer to PCB — LayoutGPT/LayoutNUWA "layout as CSS/HTML".** Serialize the board as code the LLM knows well. A playful but plausible option is to describe functional blocks as nested flexbox/grid containers ("power block: flex-row, gap 0.5mm"), lay them out with a real flexbox engine for a coarse floorplan, and then hand off to a PCB placer. LayoutNUWA's masked-HTML infill maps to "complete this partially placed board": fixed parts are given and the LLM fills the masked coordinates.
- **Transfer to PCB — LayoutPrompter ranker.** Draw N candidate placements per prompt and rank them with cheap proxies: HPWL, ratsnest crossing count, courtyard overlap area, and decap-to-pin distance. Choose exemplars by netlist similarity (retrieval-augmented placement from a library of past boards).
- **Transfer to PCB — floorplan pipelines.** HouseDiffusion's graph-masked attention maps onto a netlist-graph mask for a placement transformer (see Q2). HouseTune's "LLM draft → diffusion/optimizer refine" matches "LLM floorplan of functional blocks → analytical placer". The RLVR approach (Lara et al.) and CAD-Coder's GRPO with a geometric reward suggest fine-tuning an open LLM on KiCad placement code, with rewards from DRC pass, overlap area, HPWL and routability (Freerouting completion). The rewards are fully verifiable, which is what made CAD-Coder work.
- **Transfer to PCB — CAD code generation.** The lesson is that a program which runs and can be checked is the right output format. KiCad's Python API, or a declarative layout DSL compiled to `.kicad_pcb`, gives the same "execute and verify" loop that CadQuery gives CAD.

### Gaps
- Full Holodeck MILP formulation and DFS-vs-MILP numbers not retrieved (paper Section A.5).
- Exact error rates from the imperative-vs-declarative study (2504.05482) beyond the "most amenable" remark; the authors of 2504.05482 were not confirmed in the snippets.
- No source found that applies a Holodeck-style relational DSL to PCB placement specifically.
- LayoutVLM numeric metrics (for example collision or physics-plausibility rates) not retrieved.

## Q2. Diffusion / flow-matching / transformer models for layout, and whether a netlist-conditioned layout diffusion model is plausible for PCBs

### Takeaway
A netlist-conditioned diffusion placer already exists for chips. Lee et al. (ICML 2025) trained on **synthetic** netlists, placed unseen real circuits zero-shot, and used **guided sampling** with legality and wirelength potentials to raise legality from about 0.88 to 0.997 while cutting HPWL. Graphic-layout diffusion (LayoutDM) and flow matching (LayoutFlow) show that constraints can be injected at inference by masking. A PCB version is plausible because synthetic training data sidesteps the lack of a PCB placement dataset. It is a research project, not a quick win.

### Cited Findings
- **Chip Placement with Diffusion Models** (Lee, Nguyen, Elzeiny, Deng, Abbeel, Wawrzynek; arXiv July 2024, ICML 2025): a diffusion model samples 2D coordinates conditioned on a netlist graph with node and edge attributes. When trained on synthetic data, it produces high-quality placements on unseen realistic circuits zero-shot. Guided sampling replaces RL, which the authors call slow and poor at generalizing. On clustered IBM benchmarks, guidance raised legality from about 0.88 to 0.997 and cut HPWL 7.1% (2.976 vs 3.203 ×10⁷) without extra training. HPWL averaged 20% below DREAMPlace, with the caveat that DREAMPlace is not tuned for clustered circuits. — [arXiv 2407.12282](https://arxiv.org/pdf/2407.12282); [PMLR v267](https://proceedings.mlr.press/v267/lee25y.html)
  - A third-party review describes the guidance as a weighted sum of potentials, with overlap as the legality potential and HPWL as the wirelength potential. I did not confirm this against the paper. — [Moonlight review](https://www.themoonlight.io/review/chip-placement-with-diffusion-models)
- **DiffPlace** (Oct 2025): a conditional diffusion framework for *simultaneous* VLSI placement, motivated by RL's per-design online training and poor generalization to unseen netlists. — [arXiv 2510.15897](https://arxiv.org/html/2510.15897v1)
- **MacroDiff+** (IJCAI 2026): argues that earlier diffusion placers treat placement as purely geometric pattern generation, and adds explicit netlist-topology modeling for wirelength. — [IJCAI 2026 PDF](https://www.ijcai.org/proceedings/2026/0735.pdf)
- **LayoutDM** (CVPR 2023; code via the project page): one discrete-state diffusion model handles many layout tasks. Constraints are **injected at inference by masking or logit adjustment** rather than learned as conditioning. It beats task-specific and task-agnostic baselines on Rico and PubLayNet. — [CVPR 2023](https://openaccess.thecvf.com/content/CVPR2023/html/Inoue_LayoutDM_Discrete_Diffusion_Model_for_Controllable_Layout_Generation_CVPR_2023_paper.html); [alphaXiv overview](https://alphaxiv.org/overview/2303.08137v1)
- **LayoutFlow** (ECCV 2024; GitHub JulianGuerreiro/LayoutFlow): **flow matching** instead of diffusion. Results are comparable to SOTA and "significantly faster". One model covers tasks with different amounts of conditioning. — [ECCV 2024](https://ecva.net/papers/eccv_2024/papers_ECCV/html/5246_ECCV_2024_paper.php); [arXiv 2403.18187](https://arxiv.org/abs/2403.18187v1)
- **HouseDiffusion**: graph-constrained attention masks give a direct way to condition a Transformer denoiser on a graph. — [arXiv 2211.13287](https://arxiv.org/abs/2211.13287v1)
- **RFdiffusion** (Watson et al., Nature 620, 2023): fine-tunes the RoseTTAFold structure predictor on denoising to get a generative backbone model that handles (symmetric) **motif scaffolding**. It was motivated by the deterministic RFjoint inpainting, which gave limited design diversity. — [PMC10468394](https://pmc.ncbi.nlm.nih.gov/articles/PMC10468394)
- A separate paper treats motif scaffolding as conditional diffusion generation and unifies the conditioning protocols under Doob's h-transform. — [arXiv 2312.09236](https://arxiv.org/abs/2312.09236v3)

### Inferences
- **Plausibility for PCBs: medium-high technically, high effort.** The key enabler is Lee et al.'s synthetic-data result. A PCB generator could (1) sample random netlists that look like real boards, with power trees, MCU star topologies and passive clusters drawn from a KiCad footprint distribution, (2) place them with a classical placer plus legalizer to create targets, and (3) train a graph-Transformer denoiser over (x, y, rotation, side) per footprint, conditioned on footprint courtyard size and pad positions, net hyperedges, and fixed mechanical parts.
- **Transfer to PCB — guided sampling as the constraint mechanism.** Use courtyard overlap, board outline, keepout, decap distance and HPWL potentials as guidance. These potentials double as the DSL constraints from Q1, so an LLM-written constraint set can steer a pretrained diffusion placer without retraining. This merges the Q1 and Q2 pipelines.
- **Transfer to PCB — inpainting / motif scaffolding (LayoutDM masking, RFdiffusion).** Treat connectors, mounting holes, mechanical keepouts and human-placed parts as fixed "motifs" and inpaint the rest. This matches the real workflow, where the enclosure and connector locations are fixed first. Sampling many inpaintings gives diverse candidates for Q9-style selection.
- **Transfer to PCB — discrete rotation and side.** Footprint rotation (0/90/180/270) and board side are discrete, which suits LayoutDM-style discrete diffusion. Flow matching (LayoutFlow) is the faster alternative for the continuous x and y.
- **Risk.** PCB placement depends on semantics the netlist graph does not show: thermal behaviour, EMI, switching-loop area, and connector mating direction. A diffusion prior will not learn these from synthetic data. The LLM or constraint layer has to supply them.

### Gaps
- No published netlist-conditioned diffusion model specifically for PCB placement was found.
- DiffPlace's conditioning mechanism and quantitative results not retrieved.
- No public PCB placement dataset of significant size was found during this search; this is the main data risk.

## Q3. 2D irregular packing / nesting (no-fit polygon, Deepnest/SVGnest, bin packing): relevance to dense component packing with courtyards

### Takeaway
Nesting tools offer two directly reusable pieces: (1) **no-fit-polygon (NFP)** geometry for exact touching-but-not-overlapping placement of arbitrary courtyard shapes, and (2) fast open-source **collision-detection engines** (jagua-rs, "millions of queries per second") with a state-of-the-art strip-packing optimizer (sparrow) built on top. These suit the *legalization and compaction* step, such as squeezing passives around a fine-pitch IC or minimizing board area. They are less useful for global placement, which nesting ignores because it has no connectivity objective.

### Cited Findings
- **SVGnest** (open source, browser-based): follows the orbital NFP approach of Burke et al. (2006). The NFP is the path traced by sliding one polygon around another while they touch without overlapping; an inner-fit polygon keeps parts inside the bin. A genetic algorithm optimizes insertion order and rotation, starting from first-fit-decreasing. The authors claim "on-par with existing commercial software". — [GitHub Jack000/SVGnest](https://github.com/Jack000/SVGnest); [docs summary](https://docsearch.algolia.com/mcp/docs/repo/jack000/svgnest)
- **Deepnest** is derived from SVGnest and adds a C nesting engine, line merging, DXF support and path approximation for laser and CNC work. It uses the same GA plus NFP strategy. — [Deepnest docs index](https://docsearch.algolia.com/mcp/docs/repo/jack000/deepnest)
- Anecdotal report of NFP edge cases producing overlaps after several iterations. — [VHS forum](https://talk.vanhack.ca/t/my-open-source-nesting-program/3533)
- **jagua-rs**: a "fast and fearless" collision-detection engine for 2D irregular cutting and packing, meant as a backend for optimizers. It resolves millions of queries per second and supports strip packing, bin packing and multi-strip packing. Published in INFORMS Journal on Computing as "Decoupling Geometry from Optimization in 2D Irregular Cutting and Packing Problems". — [arXiv 2508.08341](https://arxiv.org/pdf/2508.08341); [docs.rs](https://docs.rs/jagua-rs); [INFORMS JoC](https://pubsonline.informs.org/doi/abs/10.1287/ijoc.2024.1025?af=R)
- An open-source strip-packing heuristic built on this engine notes that until then "not a single academically competitive algorithm for 2D irregular C&P problems has publicly available source code". The jagua-rs README points to **sparrow** as the state-of-the-art optimizer built on it; that 2509.13329 is the sparrow paper is my inference. — [arXiv 2509.13329](https://arxiv.org/pdf/2509.13329v1); [docs.rs](https://docs.rs/jagua-rs)
- **Geometry-aware RL for 2D irregular nesting** (2026) uses a scriptable Deepnest/SVGnest engine as an open-source GA baseline, with a 0.5° orientation grid and bounding-box-occupancy fitness. — [arXiv 2606.10611](https://arxiv.org/pdf/2606.10611)
- Related integer-programming layout work exists: GRIDS (interactive layout design with integer programming) and a hybrid CDCL + CP-SAT approach to discrete facility layout (titles only). — [arXiv 2001.02921](https://arxiv.org/pdf/2001.02921); [arXiv 2512.18034](https://arxiv.org/pdf/2512.18034)

### Inferences
- **Transfer to PCB — NFP-based legalizer and compactor.** After global placement, legalize with NFPs built from **courtyard polygons** (KiCad F.CrtYd/B.CrtYd), including non-rectangular courtyards such as connectors with overhangs and L-shaped modules. Compute the NFP of each pair at the allowed rotations, then slide each part toward its target (from the LLM or analytical placer) to the nearest feasible NFP point. Unlike a rectangle legalizer, this packs tightly where clearance is allowed.
- **Transfer to PCB — jagua-rs as the geometry kernel.** A placement search that evaluates millions of candidate moves (simulated annealing, program-parameter search from Q1, or QD from Q9) needs fast overlap tests. jagua-rs (Rust, could be wrapped for Python via PyO3) gives polygon collision queries, so the search does not need a heavy DRC call per move.
- **Transfer to PCB — modified fitness.** Nesting fitness (strip length or bin occupancy) should become a weighted sum of courtyard-feasible area plus HPWL plus decap-distance penalties. SVGnest's GA genome (order plus rotation) fits PCB footprints with four rotations and two sides.
- **Transfer to PCB — board-area minimization.** For "make the board as small as possible", strip packing with a fixed width and minimized length is exactly the formulation. Sparrow-style optimizers apply once connectivity is added as a penalty.
- **Why it might not transfer.** Nesting has no nets. Packing passives tightly can make them unroutable, for example by blocking via escape under a BGA. Use it for legalization and compaction only, with a routability margin added to courtyards (inflate by the routing-channel width).

### Gaps
- No paper found that applies NFP nesting to PCB component placement.
- Sparrow benchmark numbers and the license terms of jagua-rs/sparrow were not retrieved.

## Q4. Robotics motion planning applied to routing: RRT/PRM, visibility graphs, configuration space, MAPF (CBS, prioritized planning). Are there papers applying MAPF to PCB/VLSI routing?

### Takeaway
Yes. A 2025 paper (*PCB routing on unstructured meshes with conflict-based search*, J. Supercomputing) applies CBS directly to PCB routing on Delaunay-triangulated meshes. LG AI Research has an **RRT-PCB** that refines grid-routed solutions in continuous space. The deeper link is that PathFinder-style **negotiated congestion**, used by every major FPGA router, is a soft-constraint relative of MAPF conflict resolution. MAPF for **large (geometric) agents** (MC-CBS, up to three orders of magnitude faster than CBS) maps onto traces with width and clearance. Topological, homotopy-class routing (TopoR, JITX) is the configuration-space idea most compatible with LLM reasoning.

### Cited Findings
- **CBS** (Sharon et al., AAAI 2012): two levels, with a high-level search over a tree of agent conflicts and a low-level single-agent search. It often expands fewer states than A* while staying optimal, with speedups up to an order of magnitude. — [AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/8140)
- **Classical MAPF definition**: a tuple ⟨G, s, t⟩ with discrete time; the common objectives are makespan and sum of costs. — [MAPF definitions & benchmarks](https://par.nsf.gov/servlets/purl/10099139); [MAPF survey 2025](https://arxiv.org/html/2505.19219v1)
- **MAPF for Large Agents** (Li, Surynek, Felner, Ma, Kumar, Koenig; AAAI 2019): point-agent MAPF does not fit geometric agents, so the paper formalizes LA-MAPF and introduces **Multi-Constraint CBS** (several constraints added per high-level node, plus an admissible heuristic). It is up to three orders of magnitude faster than CBS, beats EPEA* in all cases and MDD-SAT in some. — [AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/4756); [CMU RI](https://www.ri.cmu.edu/publications/multi-agent-path-finding-for-large-agents)
- **PCB routing on unstructured meshes with conflict-based search** (2025, *The Journal of Supercomputing*): treats PCB routing as multi-robot path planning and applies CBS on Delaunay-triangulated grids ("UGPCB-CBS"). The map model combines artificial potential field path generation with Delaunay triangulation. Motivation: grid methods struggle as component density rises. Abstract only; benchmark numbers not retrieved. — [Springer](https://link.springer.com/article/10.1007/s11227-025-07569-0)
- A MAPF-style token-swapping formulation is used for multi-qubit routing on unit-distance graphs, where only one agent may occupy a node per time step. — [arXiv 2405.18785](https://arxiv.org/pdf/2405.18785)
- Off-the-shelf CBS implementation in Python: [PyPI cbs-mapf](https://pypi.org/project/cbs-mapf/)
- **PathFinder** (McMurchie & Ebeling, FPGA 1995): an iterative negotiated-congestion router in which signals negotiate for shared resources and critical signals get more say. It needs only a directed resource graph. — [ACM DOI](https://www.doi.org/10.1145/201310.201328); [TU Darmstadt slides](https://www.esa.informatik.tu-darmstadt.de/archive/twiki/pub/Lectures/AlgorithmenImChipEntwurfDe/router-pathfinder.pdf)
  - Picked as one of the FPGA symposium's "Top 25 in 20" papers. A nominator said it turned FPGA routing "from a headache with erratic results into a fairly controllable optimization problem". — [UW CSE news](https://news.cs.washington.edu/2012/03/01/cses-carl-ebeling-wins-top-25-in-20-from-fpga)
- **RRT-PCB** (LG AI Research, Dec 2024): mapping a grid route back onto the real board can create violations from grid error, so the solution is refined in continuous space with an RRT variant built for PCB, reusing grid routes to sample efficiently. — [LG AI Research blog](https://www.lgresearch.ai/blog/view?seq=510)
- RRT is fast and simple but not optimal, and RRT* fixes optimality. — [Sampling-based planning survey](https://arxiv.org/pdf/2304.14839)
- Uniform sampling struggles in narrow passages; narrow-passage-biased sampling helps. — [Disassembly path planning (BIU)](https://cris.biu.ac.il/en/publications/a-disassembly-path-planning-method-for-mechanical-products-in-nar/)
- Anytime bidirectional RRT is used for 3D cable routing, with an obstacle-based "magnetic attraction" step that pulls paths onto surfaces. — [BIT](https://pure.bit.edu.cn/en/publications/anytime-rrt-based-cable-automatic-routing-under-three-dimensional/)
- **Topological / homotopy routing**:
  - JITX defines a topo-route as a **homotopy class of paths** through the board minus the representative points of other objects, ignoring width, clearance and curvature. If geometric realization fails, it keeps a "rubber band equivalent". — [JITX docs](https://docs.jitx.com/en/4.0/essentials/physical_design/autorouter.html)
  - TopoR routes in any direction along shortest paths, not only orthogonal or 45°. — [product listing](https://www.criticalcomms.com.au/content/unknown/product/topological-pcb-autorouter-726535972); [user blog](https://wp.josh.com/2017/10/23/adventures-in-autorouting/amp/)
  - A patent abstracts the design space into a topological graph, relaxes constraints until a global topological solution exists, and then converts it to geometry. — [USPTO 7937681](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/7937681)
  - The UCSC topological routing report supports rectilinear, octilinear and Euclidean metrics, arbitrary obstacles and gridless routing. — [UCSC-CRL-97-07](https://tr.soe.ucsc.edu/sites/default/files/technical-reports/UCSC-CRL-97-07.pdf)
  - Altium contrasts topological routing (Situs) with grid expansion routers. — [Altium techdocs](https://techdocs.altium.com/display/ADOH1/Topological+Autorouting+-+Mapping+the+Changing+Space)
- **libavoid visibility-graph routing** (computational geometry, see Q6) finds optimal object-avoiding orthogonal routes over an orthogonal visibility graph, fast enough to reroute during interaction. — [libavoid docs](https://www.adaptagrams.org/documentation/libavoid.html)

### Inferences
- **Transfer to PCB — CBS / MC-CBS router with the LLM as conflict arbiter.** Each net (or each two-pin connection after Steiner decomposition) is an agent, and each layer is a copy of the graph joined by via edges. A conflict is two nets claiming overlapping clearance regions. MC-CBS (large agents) handles width and clearance natively by forbidding a whole footprint of cells per constraint. Optimal CBS will not scale to hundreds of nets, so use the bounded-suboptimal or prioritized variants. The LLM's role: (a) set **net priorities and ordering** for prioritized planning (power and high-speed first, as a designer would), and (b) at a stalled CBS node, pick which conflict to branch on and which net should yield ("let the I2C pull-up route detour, not the USB pair"). This makes the LLM a high-level search heuristic over semantic knowledge it already has.
- **Transfer to PCB — PathFinder as the strong baseline.** Negotiated congestion is the soft, iterative analog of CBS and is proven across decades of FPGA tools. A practical router should implement PathFinder on a multilayer grid or mesh and use CBS-style hard branching only for the last few unresolved conflicts. The LLM can set history and present-congestion cost multipliers per net class.
- **Transfer to PCB — RRT-PCB / continuous refinement.** Route coarsely on a grid (fast A*/PathFinder), then refine each trace in continuous space with RRT* or shortcutting to remove grid artifacts and allow any-angle or 45° geometry. Narrow-passage-biased sampling fits fine-pitch escape regions.
- **Transfer to PCB — homotopy-first routing (most LLM-friendly).** LLMs are much better at qualitative topology ("route the SPI bus north of U4, between C7 and C8, on layer 1") than at coordinates. Let the LLM specify a **homotopy class**, such as an ordered list of obstacles to pass left or right of plus layer changes, and let a rubber-band geometric realizer (JITX-style) or a funnel/shortest-path-in-polygon algorithm make it concrete. Crossings between nets in the same layer can be checked topologically before any geometry exists, so the LLM gets cheap, exact feedback.
- **Transfer to PCB — visibility graphs.** For 1–2 layer boards or a global routing estimate, an orthogonal or octilinear visibility graph over courtyard obstacles (libavoid-style) gives exact shortest obstacle-avoiding routes without a grid. It is useful as a routability estimator during placement.

### Gaps
- UGPCB-CBS benchmark numbers and comparisons (for example against Freerouting) not retrieved.
- No VLSI detailed-routing paper with an explicit MAPF formulation was found in these searches (searches returned general MAPF only).
- RRT-PCB quantitative results not retrieved.

## Q5. Game AI and search: AlphaZero/MuZero-style MCTS for placement/routing, puzzle solvers (Flow Free / Numberlink via SAT), Zachtronics-style human strategies

### Takeaway
MCTS has been used for chip macro placement (EfficientPlace, ICML 2024: global tree search plus local RL) and in an MIT thesis on PCB synthesis (MCTS-generated datasets for offline RL). Numberlink/Flow Free is a toy version of single-layer routing. It is NP-complete, and SAT encodings exist (Permanganate, a 2025 Leiden thesis), which suggests SAT/CP-SAT for small, dense local routing regions. I found no rigorous source on Zachtronics-style human strategies.

### Cited Findings
- **EfficientPlace** (ICML 2024): pairs global tree search with an RL agent for local policy learning in macro placement, with strong quality in short runtimes. — [mlanthology](https://mlanthology.org/icml/2024/geng2024icml-reinforcement)
- **Kaphle, MIT thesis (2022)**: uses MCTS to self-generate datasets for PCB synthesis ("LFS") and trains off-policy RL offline on them. It starts from designs that other methods left with constraint violations, and the MCTS feedback loop performed best among the methods tried. — [DSpace@MIT](https://dspace.mit.edu/handle/1721.1/145108)
- **Iowa State (Youbiao He, 2020)**: frames PCB and IC routing as sequential decisions solved with RL plus tree search. — [ISU CS](https://www.cs.iastate.edu/phd-research-proficiency-exam-youbiao-he)
- Patent filings titled "Electrical circuit design" describe RL with sequential-Monte-Carlo look-ahead for choosing connection routes, building on AlphaZero-style MCTS. Assignee not verified. — [USPTO 12019968](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/12019968)
- **Numberlink / Flow Free**: the Zig-Zag Numberlink variant popularized by Flow Free is NP-complete. — [arXiv 1410.5845](https://arxiv.org/abs/1410.5845)
- **Permanganate** (Rust) solves Numberlink/Flow Free by encoding it as SAT, and supports non-rectangular boards, bridges and warps that earlier "path shape" solvers could not. — [docs.rs permanganate](https://docs.rs/permanganate)
- A Leiden bachelor thesis (2025) solves Numberlink with SAT, compares against backtracking, and covers encodings for line connection, number constraints, **cycle prevention**, and hexagonal cells. — [LIACS thesis](https://theses.liacs.nl/pdf/2025-2026-LelipalyJJoshua.pdf)
- A Flow Free "bridges" variant (non-planar crossings) is modeled by splitting bridge tiles into horizontal and vertical nodes, which mirrors vias and layer changes. — [ITB paper](https://informatika.stei.itb.ac.id/~rinaldi.munir/Stmik/2025-2026/Makalah2026%5C13524011_Muhammad%20Iqbal%20Raihan_Solving%20Flow%20Free%20Puzzles%20with%20Non-Planar%20Path%20Intersections%20via%20Backtracking%20An%20Algorithmic%20Extension%20to%20the%20Bridges%20Variant.pdf)

### Inferences
- **Transfer to PCB — SAT/CP-SAT for local dense regions (Numberlink analog).** Cut out a small window, such as BGA or QFN escape, a connector fan-out, or a congested corner. Discretize it on a fine grid per layer and encode connectivity per net, cell exclusivity with clearance as neighbourhood exclusion, via cells as "bridges", and cycle and dangling-stub prevention, exactly as Numberlink SAT encodings do. Solve exactly with CP-SAT or a SAT solver. This complements a global PathFinder or CBS router: global routing assigns window boundary crossings ("pins" on the window edge) and SAT completes the inside. The LLM decides *which* windows are hard and which boundary-crossing assignments to try.
- **Transfer to PCB — MCTS over placement order and coarse decisions.** EfficientPlace's split (tree search for global decisions, a learned or cheap policy for local ones) maps onto PCB as follows. The tree nodes are decisions such as block-to-region assignment, side (top or bottom), and orientation of major ICs. Rollouts use a fast analytical placer plus a routability estimate. The LLM can serve as the *prior policy* (AlphaZero's P(s,a)), proposing the top-k actions at each node from design knowledge, while MCTS checks them against cheap rollouts.
- **Transfer to PCB — MCTS-generated data (Kaphle).** Use search to create (state, good action) data from fixing DRC violations and fine-tune a small model on it. This is a self-improvement loop that needs no human-labelled layouts.
- **Zachtronics-style human strategy.** No sources found. Plausible human heuristics such as "route the hardest net first", "leave channels", "bus-first" and "fan out before routing" are better captured by eliciting them as LLM prompts or library macros and evaluating them with evolved heuristics (Q7).

- No AlphaZero/MuZero paper specifically for PCB placement found; AlphaChip-style RL is covered elsewhere and was not re-researched here.
- No sources on Zachtronics-game human strategies as applied to routing.

## Q6. Graph drawing and VLSI-inspired layout: orthogonal graph drawing, Sugiyama layered layouts, constrained force-directed / stress majorization (WebCola, IPSep-CoLa), relevance to schematic-flow-aware placement

### Takeaway
Graph drawing has mature, open-source solvers for exactly the constraints a "schematic-flow-aware" PCB placer needs. **Constrained stress majorization** (IPSep-CoLa; WebCola; Graphviz `ipsep`) supports separation constraints (A left of B by at least d), alignment, non-overlap and cluster containment. **HOLA** (InfoVis 2015 best paper) produces orthogonal layouts rated comparable to hand-made ones. **libavoid** routes orthogonal connectors over a visibility graph with nudging. **ELK Layered** (Sugiyama) with port constraints already draws netlists as schematics (netlistsvg). **Cassowary** (behind Apple Auto Layout) gives prioritized linear constraints. Together they are a ready global-placement engine whose constraints an LLM could write.

### Cited Findings
- **IPSep-CoLa** (Dwyer, Koren, Marriott, IEEE TVCG 2006): incremental stress-majorization layout under separation constraints. Slides also list alignment constraints and show results on a large directed graph. — [Dwyer slides (UBC)](https://www.cs.ubc.ca/~tmm/courses/533-09/slides/dwyer.subset.pdf); [reference list in arXiv 2403.15811](https://arxiv.org/pdf/2403.15811)
- **Graphviz `constrained_majorization_ipsep.c`** supports directed-edge constraints, node non-overlap, cluster containment and cluster/node non-overlap. — [Graphviz source docs](https://archive.graphviz.org/Archive/development/doxygen/html/constrained__majorization__ipsep_8c_source.html)
- **WebCola (cola.js)** offers constrained and unconstrained layouts that monotonically reduce stress. Whether it uses IPSep-CoLa internally was not confirmed. — [cola.js](https://ialab.it.monash.edu/webcola/examples/unconstrained.html)
- Wang et al. (IEEE TVCG 2018) reformulate stress majorization to handle constraints, including cluster separation, without a constrained solver. — [KOPS Konstanz](https://kops.uni-konstanz.de/handle/123456789/41124)
- **HOLA** (Kieffer, Dwyer, Marriott, Wybrow; IEEE TVCG 22(1), 2016; InfoVis 2015 Best Paper): aesthetic criteria came from user studies, and users rated the output better than the best orthogonal algorithm of the time and comparable to hand-made layouts. Now part of Adaptagrams C++ (`libdialect`, `doHOLA`). — [paper PDF](https://ialab.it.monash.edu/~dwyer/papers/hola2015.pdf); [award](https://ialab.it.monash.edu/2015/10/infovis-2015-best-paper-award/); [Adaptagrams libdialect](https://www.adaptagrams.org/documentation/libdialect.html); [skieffer/hola](https://www.github.com/skieffer/hola)
- **ARCOL** (2026) adds aspect-ratio control to HOLA through a soft constraint in stress minimization. — [arXiv 2603.29618](https://arxiv.org/abs/2603.29618)
- **libavoid** (Wybrow, Marriott, Stuckey): "Orthogonal connector routing" (GD '09) computes optimal object-avoiding routes that minimize a monotonic function of length and bends, fast enough for interactive rerouting. "Seeing Around Corners" (2014) adds obstacle-hugging canonical routes and a 1-bend visibility graph for speed. Used in Inkscape and Dunnart; also covers orthogonal hyperedge routing. — [libavoid docs](https://www.adaptagrams.org/documentation/libavoid.html); [Orthogonal connector routing](https://findanexpert.unimelb.edu.au/scholarlywork/863594-orthogonal-connector-routing); [Seeing Around Corners](https://findanexpert.unimelb.edu.au/scholarlywork/916403-seeing%20around%20corners-%20fast%20orthogonal%20connector%20routing)
  - Nudging spreads edges across available space and minimizes crossings globally; one paper calls it too slow for interactive frame rates. Details are in Wybrow's thesis section "Nudging shared paths". — [EditLens arXiv 1612.05064](https://arxiv.org/pdf/1612.05064); [Wybrow thesis](https://ialab.it.monash.edu/~mwybrow/papers/wybrow-thesis-2008.pdf)
- **netlistsvg** draws SVG schematics from Yosys JSON netlists using **elkjs**, the Eclipse Layout Kernel's layered/Sugiyama engine. — [GitHub netlistsvg (fork)](https://github.com/shuckc/netlistsvg)
- **d3-hwschematic** also uses ELK and recommends `org.eclipse.elk.portConstraints = FIXED_ORDER` (or FREE) for hardware schematics. — [npm d3-hwschematic](https://www.npmjs.com/package/d3-hwschematic); [README](https://cdn.jsdelivr.net/npm/d3-hwschematic@0.1.6/README.md)
- **Cassowary** (Badros, Borning, Stuckey 2001): an incremental dual-simplex solver for linear equality and inequality UI constraints. Constraints have strengths (required, strong, medium, weak), and the weakest are violated first when the system is infeasible. It can add and remove constraints at runtime with minimal rework, and it powers Apple AutoLayout. There are Rust, JS and Kotlin ports. — [UW tech report](https://constraints.cs.washington.edu/solvers/cassowary-tr.html); [docs.rs cassowary](https://docs.rs/cassowary); [cassowary.js docs](https://docsearch.algolia.com/mcp/docs/repo/slightlyoff/cassowary.js)

### Inferences
- **Transfer to PCB — constrained stress majorization as the global placer for "schematic-flow-aware" placement.**
  - *Stress term*: target distance between footprints = a function of netlist graph distance, weighted by net criticality (shorter for decoupling caps and crystal loops, longer for unrelated blocks).
  - *Separation constraints*: express signal flow, e.g. `x(J_in) + d ≤ x(U_filter) ≤ x(U_adc) ≤ x(U_mcu) ≤ x(J_out)`, and power flow such as `x(J_pwr) < x(U_reg) < x(load)`.
  - *Alignment constraints*: rows and columns of identical passives, centered LED arrays, connectors aligned to an edge.
  - *Cluster containment*: functional blocks such as "power", "RF" and "analog front-end" become rectangles that hold their members and do not overlap other clusters (supported by Graphviz ipsep).
  - *Non-overlap*: courtyard rectangles.

  The LLM writes these constraints, which are linear and easy to explain, and the solver guarantees them. It is fast enough to re-solve interactively after each LLM edit.
- **Transfer to PCB — Sugiyama/ELK Layered seeding.** Build a directed graph from the schematic (power source → regulators → loads; inputs → processing → outputs) using pin types (input/output/power_in/power_out in KiCad symbols), run ELK Layered with FIXED_ORDER port constraints, and take the layer index as the initial x-ordering of blocks. netlistsvg shows this pipeline already produces readable schematics from netlists. The same drawing doubles as a "signal-flow map" for the LLM to reason over.
- **Transfer to PCB — HOLA for orthogonal, human-like block arrangement.** HOLA's study-derived aesthetics (orthogonality, aligned trees, compactness) match what designers call a "clean" board. Run it at block level (one node per functional block, edges weighted by net count) to propose a floorplan an LLM can then adjust.
- **Transfer to PCB — libavoid as a routing preview and routability metric.** During placement, route ratsnest edges as orthogonal connectors that avoid courtyards, with nudging to spread parallel connectors. Total bends, crossings and channel overflow give a cheap routability signal far better than straight-line ratsnest crossings. On simple 2-layer boards it could even serve as a first-pass router: orthogonal hyperedge routing handles multi-pin nets.
- **Transfer to PCB — Cassowary strengths as the priority system.** Map DRC-hard constraints (outline, overlap) to `required`, electrical-critical (decap ≤ 1.5 mm, crystal ≤ 5 mm) to `strong`, design-intent (signal-flow order, alignment) to `medium`, and aesthetics (symmetry, equal spacing) to `weak`. Incremental add and remove fits a conversational loop ("now also keep J3 at least 5 mm from the edge"). Limitation: Cassowary handles linear constraints only, so non-overlap needs disjunctions, either as fixed left/right/above/below decisions chosen by the LLM or by an outer search.

### Gaps
- Whether WebCola implements IPSep-CoLa internally, and a Python binding for constrained stress majorization, were not confirmed.
- No paper found that applies constrained graph drawing directly to PCB component placement.

## Q7. Program synthesis / LLM-evolved algorithms (FunSearch, AlphaEvolve, EoH, ReEvo, OPRO): LLMs writing heuristics for packing, routing, scheduling; reported gains

### Takeaway
LLM-guided evolution of *code* (not layouts) has beaten classic packing heuristics and, by 2025–2026, VLSI placement heuristics. **FunSearch** improved online bin packing over first-fit and best-fit on every OR-Library set. **EoH** (ICML 2024) and **ReEvo** (NeurIPS 2024) improved on FunSearch's sample efficiency. **AlphaEvolve** (May 2025) found new circle-packing constructions and reports chip-design use, and OpenEvolve offers an open-source reimplementation. In EDA, LLM-evolved **macro placement ordering** (OrderPlace, 2026: −34% and −14% wirelength vs WireMask-EA and EGPlace), **VLM-proposed region constraints plus evolution** (VeoPlace) and **LLM-evolved analytical global-placement optimizers** (2025) show it transfers to physical design. The PCB router and placer heuristics are natural targets.

### Cited Findings
- **FunSearch** (DeepMind; code and discovered bin-packing heuristics on GitHub): evolves programmatic heuristics that choose a bin for each arriving item. Excess bins over the lower bound on OR-Library:

  | Set | First fit | Best fit | FunSearch |
  |---|---|---|---|
  | OR1 | 6.42% | 5.81% | 5.30% |
  | OR2 | 6.45% | 6.06% | 4.19% |
  | OR3 | 5.74% | 5.37% | 3.11% |
  | OR4 | 5.23% | 4.94% | 2.47% |

  The gap widens with instance size. The heuristic is readable code. — [Wikipedia: FunSearch](https://en.wikipedia.org/wiki/FunSearch); [GitHub google-deepmind/funsearch](https://github.com/google-deepmind/funsearch)
  - A reported result about 0.03% above optimum on a 100k-item Weibull instance could not be independently verified; one paper notes the Weibull priority function was not open-sourced. — [Wikipedia: FunSearch](https://en.wikipedia.org/wiki/FunSearch)
- **EoH — Evolution of Heuristics** (Liu et al., ICML 2024 oral): evolves natural-language "thoughts" alongside code. It beats handcrafted heuristics and FunSearch on three combinatorial benchmarks, and on online bin packing it got a significantly better heuristic with a low query budget. — [arXiv 2401.02051](https://arxiv.org/html/2401.02051v3); [PMLR](https://proceedings.mlr.press/v235/liu24bs.html)
- **ReEvo** (Ye et al., NeurIPS 2024): "Language Hyper-Heuristics" in which evolutionary search is guided by LLM **reflections as verbal gradients**. It is SOTA or competitive across 12 combinatorial optimization settings, including black-box ones, and more sample-efficient than prior LLM hyper-heuristics. — [arXiv 2402.01145](https://arxiv.org/abs/2402.01145v3)
- **OPRO** (Yang et al., DeepMind, ICLR 2024; github.com/google-deepmind/opro): the meta-prompt holds past solution–score pairs plus the task description, and the LLM proposes new solutions each step. Optimized prompts beat human ones by up to 8% on GSM8K and up to 50% on BBH. — [arXiv 2309.03409](https://arxiv.org/pdf/2309.03409); [ICLR proceedings](https://proceedings.iclr.cc/paper_files/paper/2024/hash/3339f19c5fcee3ad74502947a32be9e6-Abstract-Conference.html)
- **AlphaEvolve** (DeepMind blog, May 14, 2025): an evolutionary coding agent in which Gemini models propose programs, automated evaluators score them, and the evolutionary loop keeps the best. — [DeepMind blog](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)
  - Secondary coverage: Gemini Flash gives breadth and Pro gives depth; Google reports gains in data centers, chip design and AI training. — [TechRepublic](https://www.techrepublic.com/article/news-google-deepmind-alphaevolve-coding-ai/)
  - Circle packing, per secondary sources: sum of radii for n=26 went from 2.634 to 2.635, n=32 from 2.936 to 2.937, and n=21 in a perimeter-4 rectangle from 2.364 to 2.3658. — [36kr](https://eu.36kr.com/en/p/3388453754962049)
  - **OpenEvolve** (open source) reimplements AlphaEvolve and reproduced n=26 circle packing at 2.634, about 99.97% of the reported value. — [HF blog: OpenEvolve](https://huggingface.co/blog/codelion/openevolve)
  - AlphaEvolve is offered on Google Cloud through a codelab and early access. — [Google codelab](https://codelabs.developers.google.com/alphaevolve-on-google-cloud-1)
- **OrderPlace** (June 2026): LLM-driven evolution of the **order** in which macros are placed, filtered by a cheap proxy. On ISPD 2005 it cuts wirelength 34.04% vs WireMask-EA and 14.08% vs EGPlace. — [Takara TLDR 2606.08904](https://tldr.takara.ai/p/2606.08904); [EmergentMind](https://www.emergentmind.com/papers/2606.08904)
- **VeoPlace — "See it to Place it: Evolving Macro Placements with Vision-Language Models"** (ICML 2025; NeurIPS 2026 poster; Microsoft Research): a VLM *without fine-tuning* proposes **subregion constraints** that steer a base placer, and evolutionary search refines the proposals. SOTA on 4 of 7 circuits in the ICML version; the later version claims it beats the best learning-based approach on 9 of 10, so the versions disagree. — [ICML 2025](https://icml.cc/virtual/2025/51511); [NeurIPS 2026 poster](https://neurips.cc/virtual/2026/poster/153841); [MSR](https://www.microsoft.com/en-us/research/?p=1167796)
- **Evolution of Optimization Algorithms for Global Placement via LLMs** (Apr 2025): LLMs evolve the core optimizer of analytical global placement (initialization, preconditioning, line search) through an LLM-based genetic flow. — [arXiv 2504.17801](https://arxiv.org/abs/2504.17801)
- HiFo-Prompt (hindsight/foresight prompting for LLM heuristic design) and X-evolve (evolving the solution space with LLMs) are 2025 follow-ups (titles only). — [arXiv 2508.13333](https://arxiv.org/pdf/2508.13333); [arXiv 2508.07932](https://arxiv.org/pdf/2508.07932)

### Inferences
- **Transfer to PCB — evolve the router's net-ordering and cost functions (FunSearch/EoH/ReEvo pattern).** Fix the skeleton (PathFinder or A* rip-up-and-reroute on a KiCad-derived grid) and let the LLM evolve `priority(net, state) -> float` and `edge_cost(cell, net, history) -> float`. The evaluator is routing completion rate, via count, total length and DRC errors over a benchmark of 20–50 real KiCad boards (open-hardware projects). This is the same structure as FunSearch's bin-packing priority function. Expected payoff is high because rip-up-and-reroute quality depends heavily on net-ordering heuristics, and the evaluator is fully automatic.
- **Transfer to PCB — evolve placement ordering (OrderPlace pattern).** Sequential or constructive PCB placers (anchor first, then dependents, as in Holodeck and RoomCraft) are sensitive to order. Let the LLM evolve the ordering heuristic, for example "connectors → MCU → regulators → decaps by pin criticality → the rest by net degree", with a cheap proxy (HPWL plus overlap after greedy placement) as the filter.
- **Transfer to PCB — VLM-proposed region constraints plus a classical placer (VeoPlace pattern).** Render the board, have a VLM propose rule areas ("rooms") for each functional block, run a classical placer inside the regions, and let an evolutionary loop mutate the region proposals. KiCad already supports rule areas and multichannel "rooms", so the output maps onto native objects. This is one of the most direct transplants: same problem shape (placement), same tool split (VLM for coarse, optimizer for fine), and published gains.
- **Transfer to PCB — evolve the analytical placer itself (2504.17801).** If the project uses a DREAMPlace-like PCB placer, its initialization, preconditioner and density schedule are evolvable code.
- **Transfer to PCB — OPRO as the inner loop of an LLM placer.** For a specific board, keep a meta-prompt of past (placement-parameter set, score breakdown) entries and ask the LLM for the next set. This is cheap, and it lets the LLM see which constraints trade off.
- **Practical tooling.** OpenEvolve (open source) and the FunSearch repo give ready loops. ReEvo-style "reflections" can draw on DRC reports and render critiques, so the verbal gradient carries real feedback ("the via field under U1 blocks 6 nets").
- **Why it might not transfer.** Evaluations are expensive (a routing run per candidate), so use EoH's low-query-budget regime and small proxy boards. Overfitting to the benchmark set is a real risk, so hold out boards.

### Gaps
- The FunSearch reproduction claim (a 2025 paper matching 5.30% on binpack1) appeared in search snippets but the specific paper was not confirmed.
- AlphaEvolve's chip-design use is described only at blog level; I found no details of what was optimized (circuit-level vs placement).
- No paper found applying LLM-evolved heuristics to PCB routing specifically.

## Q8. Analogies from other physical-design domains: protein design, urban/road networks, chip-package co-design, microfluidic chips, quantum chips, photonic ICs, wire harnesses

### Takeaway
Several neighbouring fields solve near-identical problems with transferable twists. **Microfluidics**: length-matched escape routing with DME Steiner trees plus min-cost flow, and negotiated-congestion PCB escape routing. **Quantum chips**: frequency-aware electrostatic placement that repels interfering components, a model for EMI and noise-aware PCB placement. **Photonics**: bending-aware wirelength and curvy A* routing with adaptive crossing insertion. **Wire harnesses**: Pareto routing that trades length against bundling. **Chip-package**: min-cost max-flow RDL routing with 100% completion and routability-driven bump assignment, a model for MCU/FPGA pin assignment. **Urban planning**: tensor-field-guided street networks, a model for preferred routing direction. **Protein design**: motif scaffolding as conditional diffusion (see Q2).

### Cited Findings
- **Microfluidics**:
  - *RABER*: control-layer escape routing in which microvalves share control ports. It notes earlier routers followed PCB escape routing and assumed one port per valve. — [TUM PDF](https://mediatum.ub.tum.de/doc/1747600/1747600.pdf)
  - *PACOR* (2015): length matching so control signals arrive together, using **deferred-merge-embedding (DME) Steiner trees**, **min-cost-flow simultaneous escape routing** and bounded-length detouring. 100% routing completion in simulations. — [NYCU repository](https://ir.lib.nycu.edu.tw/handle/11536/135751)
  - *McDaniel et al.* (IEEE TCAD 2017): extends a **negotiated-congestion single-terminal escape router** for the PCB that drives a digital microfluidic biochip, relaxing pin assignment to cut PCB layers. — [UCR archive PDF](https://webarchive.ucr.edu/public/archived-sites/microfluidics.cs/microfluidics.cs.ucr.edu/media/371/tcad17-pcb_escape_routing4429.pdf)
  - *DTU theses*: negotiation-style Pathfinder for the control layer, and Lee/Hadlock grid routing for flow and control channels. — [Rasmussen 2014](https://www.imm.dtu.dk/~pop/publications/Rasmussen2014aa-Routing%20algorithm%20for%20the%20cont-.pdf); [Hørslev-Petersen 2013](https://www.imm.dtu.dk/~pop/publications/Horslev-Petersen2013aa-Routing%20Algorithms%20for%20Flow-ba-.pdf)
  - *Sequence-pair flow-layer co-design* (JCAD 2022): placement and routing together, routing order by Manhattan distance, negotiation to reduce crossings. — [JCAD](https://www.jcad.cn/article/doi/10.3724/SP.J.1089.2022.19445)
- **Quantum chips — Qplacer** (Duke/MIT/ASU; ISCA 2025 per DAC tutorial): a **frequency-aware electrostatic** placer against crosstalk. A frequency assigner isolates qubits and resonators in frequency, padding and resonator partitioning add flexibility, and components are modeled as charges with a "frequency repulsive force". Reported area savings differ by source: one summary says 26.1% and 22.5% less area than manual design and classical placers, while the paper reports 2.14× average area reduction vs manual. A companion qGDP handles legalization and detailed placement. — [arXiv 2401.17450](https://www.arxiv.org/abs/2401.17450v3); [Quantum Zeitgeist](https://quantumzeitgeist.com/qplacer-duke-mit-and-asus-innovative-solution-to-quantum-computing-crosstalk-challenges/); [DAC quantum tutorial](https://archive.dac.com/portals/0/62dac/quantum_tutorial.5ea54a3ce6.pdf)
  - A quantum design-automation survey says superconducting placement prioritizes crosstalk and decoherence. Routing uses A* among other methods, with impedance matching and crosstalk as key constraints. — [arXiv 2511.10479](https://arxiv.org/pdf/2511.10479)
  - Placing and routing qLDPC codes on multilayer superconducting hardware (2025). — [arXiv 2507.23011](https://arxiv.org/html/2507.23011v2)
- **Photonic ICs**:
  - *APR* (Oct 2024, open source): curvy-waveguide detailed routing with grid-based A* and **adaptive crossing insertion**. DRV-free, with about 14% lower insertion loss; argues that electrical-routing algorithms ignore bending and insertion loss. — [arXiv 2410.01260](https://arxiv.org/html/2410.01260v1)
  - *Apollo* (2025): GPU-accelerated, routing-informed PIC placement with a **bending-aware wirelength model**, replacing force-directed placers limited to small benchmarks. — [arXiv 2504.18813](https://arxiv.org/html/2504.18813v2)
  - *LiDAR 2.0* (ISPD 2025): hierarchical curvy-waveguide routing. — [arXiv 2505.17239](https://arxiv.org/html/2505.17239v1)
  - Joint waveguide and metal routing for large active PICs. — [arXiv 2509.23764](https://arxiv.org/pdf/2509.23764v1)
- **Wire harness**:
  - *Karlsson et al.* (Chalmers/Volvo, Computer-Aided Design 2024): 3D harness routing that trades total cable length, **bundling of shared paths** and avoidance of restricted zones. A deterministic algorithm generates candidate topologies and approximates a **Pareto front**, reaching near-optimal results in seconds to minutes on industrial cases and beating a stochastic solver. Keywords include Lagrangian relaxation. — [Chalmers](https://research.chalmers.se/en/publication/540371)
  - *TU Delft*: a two-step hybrid of road-map path finding and refinement, in which the number of clamps is an output of routing. — [TU Delft](https://repository.tudelft.nl/file/File_e00f6f6b-a232-4af2-bea6-4150ed41044c?preview=1)
  - *Beihang*: main-channel plus undirected-graph shortest path, about 50% efficiency gain. — [BUAA](https://research.buaa.edu.cn/en/publications/the-research-on-routing-optimization-method-using-undirected-grap/)
- **Chip-package co-design**:
  - *ISPD 2026 talk*: any-angle die-to-die routing with via constraints and shielding-aware reservation (NTU/Synopsys). — [ISPD 2026 slides](https://ispd.cc/slides/2026/protected/slides_3_3.pdf)
  - *Zhuang et al.* (ACM TODAES 2025): RDL routing in chiplet co-design, with Maximal-Independent-Set pin assignment and a network-flow router. — [UArk PDF](https://e3da.csce.uark.edu/pub/doc/2025/Z.Zhuang-ACM.TODAES-2025.pdf)
  - *Fang & Chang* (ICCAD 2008): a min-cost max-flow multi-RDL router that guarantees 100% completion. — [ICCAD PDF](https://cecs.uci.edu/~papers/iccad08/PDFs/Papers/07A.4.pdf)
  - *Chen et al.* (ASP-DAC 2014): routability-driven bump assignment for RDL and substrate, inspired by board escape routing. — [ASP-DAC PDF](https://www.aspdac.com/aspdac2014/technical_program/pdf/6B-3.pdf)
- **Urban / road networks**:
  - *Interactive Procedural Street Modeling* (Chen, Esch, Wonka, Müller, Zhang; SIGGRAPH 2008): street networks generated by designing an underlying **tensor field** (brush strokes, smoothing, constraints, noise and rotation fields) and then editing the graph. — [project page](https://www.sci.utah.edu/~chengu/street_sig08/street_project.htm); [PDF](https://web.engr.oregonstate.edu/~zhange/images/street_sig08.pdf)
  - *Galin et al.* (2011): hierarchical, terrain-aware road networks with graph arcs that store highway, major and minor road paths. — [Purdue PDF](https://www.cs.purdue.edu/homes/bbenes/papers/Galin11CGF.pdf)
- **Protein design**: RFdiffusion motif scaffolding (see Q2). — [PMC10468394](https://pmc.ncbi.nlm.nih.gov/articles/PMC10468394)

### Inferences
- **Transfer to PCB — Qplacer to EMI/noise-aware electrostatic placement.** Extend a DREAMPlace-style electrostatic PCB placer with **extra repulsive "charges" between aggressor/victim classes**. Aggressors include switching nodes, inductors, clock oscillators and RF PAs; victims include ADC inputs, crystals and sensitive analog. Repulsion strength depends on frequency overlap and sensitivity. The LLM labels the classes from the schematic (it can recognise a buck converter's SW node). This is a concrete way to encode "keep noisy things away from quiet things" as a differentiable term.
- **Transfer to PCB — PACOR to length-matched buses.** DDR, parallel RGB LCD, and HDMI/MIPI skew groups need matched lengths. DME Steiner trees plus min-cost-flow escape plus bounded-length detours (meanders) are a proven recipe for matched escape routing. McDaniel et al. show negotiated-congestion escape routing already on PCBs.
- **Transfer to PCB — photonic bending-aware cost to high-speed and RF traces.** Bending-aware wirelength (Apollo) and curvy A* (APR) map onto RF microstrip and multi-gigabit pairs, where bends and vias carry a signal-integrity cost. APR's adaptive crossing insertion corresponds to *adaptive via insertion*: price layer changes by SI impact per net class.
- **Transfer to PCB — harness Pareto bundling to bus bundling.** Add a reward for nets of the same bus sharing a corridor (bundling), the opposite of congestion penalties, and present a length-vs-bundling Pareto front. Buses routed together look professional and simplify length matching.
- **Transfer to PCB — chip-package to MCU/FPGA pin assignment co-optimization.** Bump assignment for routability corresponds to **GPIO/pin-mux assignment**. Many MCU and FPGA pins can be swapped (any GPIO for an LED, alternative UART/SPI pin maps). Let the LLM, which knows the pin-mux tables from datasheets, propose valid swaps, and score them by routability (crossing count via min-cost flow or the libavoid preview). Feed the chosen assignment back to the schematic. This is a strong but underused PCB lever.
- **Transfer to PCB — tensor fields to preferred-direction routing guidance.** Build a smooth tensor field from board edges, connector orientations and major IC pin-row directions, and derive per-layer preferred directions (layer 1 follows the major eigenvector, layer 2 the minor). This replaces fixed "horizontal/vertical per layer" rules with a field fitted to the board. Streamlines of the field could also seed bus corridors or river routing. The LLM can add "brush strokes" ("buses here should run diagonally toward the connector").
- **Transfer to PCB — quantum routing with impedance as a hard constraint** mirrors controlled-impedance traces, which need fixed width per layer stack-up. This is already standard PCB practice, so there is little new to transfer.

### Gaps
- Most findings come from abstracts; algorithm internals (for example PACOR's DME parameters, Qplacer's force formulation) not verified in full text.
- I found no source applying tensor-field street modeling to circuit routing; the transfer is speculative.
- AlphaFold-style iterative "recycling" refinement was not separately researched (web-search budget exhausted).

## Q9. Quality-diversity (MAP-Elites) and generative design (Autodesk-style) for producing multiple diverse layout candidates for a human or LLM to choose among

### Takeaway
MAP-Elites keeps the best solution in each cell of a grid over behaviour descriptors. It has been used for building layouts (T-DominO), urban layouts (ARCH-Elites) and constrained room layouts (FI-MAP-Elites), and to build training data for a GPT layout generator (TileGPT). Autodesk's Project Discover generated about 10,000 office layouts scored on six metrics and let humans choose. pyribs is a mature Python library. For PCBs, an archive over (board area × layer/via count × aspect ratio, or thermal spreading) would give the user or LLM a *menu* of real trade-offs instead of one answer.

### Cited Findings
- **pyribs** (Python): implements the RIBS framework (archive + emitters + optimizer) and is the official implementation of CMA-ME, CMA-MEGA and CMA-MAE. Archives are heatmap-like grids that hold the best solution per region of measure space. Early docs said it focuses on fixed-dimensional continuous domains and pointed to qdpy and sferes for discrete ones. — [GitHub icaros-usc/pyribs](https://github.com/icaros-usc/pyribs); [docs](https://ribs.readthedocs.io); [PyPI](https://pypi.org/project/ribs/)
- **T-DominO**: MAP-Elites with a tournament-dominance objective, applied to building layouts for a real residential complex, using Wave Function Collapse (WFC) to generate layouts. Four objectives, one constraint, three feature dimensions. — [arXiv 2207.01439](https://arxiv.org/pdf/2207.01439)
- **ARCH-Elites**: MAP-Elites that reconfigures large urban layouts at real Boston sites, using a pre-trained surrogate instead of costly simulation. — [SOTAVerified](https://sotaverified.org/papers/arch-elites-quality-diversity-for-urban)
- **Constrained MAP-Elites**: user-driven, sampling alternatives from a window of behaviour space for architectural layout. — [AI4Europe](https://www.ai4europe.eu/research/ai-catalog/constrained-map-elites)
- **FI-MAP-Elites** (PCG 2022): constrained QD for room-based environments with topological and geometric constraints; code on GitHub. — [GitHub konsfik/FI-MAP-Elites](https://github.com/konsfik/FI-MAP-Elites)
- **TileGPT** (per a third-party review): MAP-Elites builds an attribute-labelled design dataset, a GPT is fine-tuned on it, and **WFC** refines outputs so they satisfy constraints. — [Moonlight review](https://www.themoonlight.io/es/review/generative-design-through-quality-diversity-data-synthesis-and-language-models)
- **Autodesk Project Discover / MaRS Toronto office**: about 10,000 generated options for a 60,000 ft² office, scored on adjacency preference, work-style preference, "buzz", productivity, daylight and views. Fixed constraints included the space, amenity counts and fixed core and mechanical rooms. It led to Project Refinery (Dynamo) and later Project Rediscover. — [BrainStation](https://brainstation.io/magazine/autodesks-new-toronto-office-displays-algorithm-driven-generative-design); [CSE Magazine](https://www.csemag.com/articles/case-study-autodesks-generative-design-artificial-intelligence/); [Autodesk University](https://www.autodesk.com/autodesk-university/article/Hands-Project-Rediscover-Generatively-Designing-Autodesk-Toronto-Office-2020)

### Inferences
- **Transfer to PCB — MAP-Elites over PCB behaviour descriptors.** Possible descriptors: (1) board area or aspect ratio, (2) top-only vs double-sided component fraction, (3) via count or layer usage, (4) "signal-flow straightness" (alignment with the Sugiyama ordering), (5) thermal spread (distance between hot parts). Fitness is a weighted sum of HPWL, routability preview and constraint satisfaction. The archive is a *design-space map*: "here is the smallest board, the cheapest-to-assemble single-sided board, and the most routable board". The LLM can summarise trade-offs for the human or pick a cell given stated priorities.
- **Transfer to PCB — the LLM as an emitter.** Instead of Gaussian mutations, an "LLM emitter" proposes edits ("move the power block to the bottom-right and flip U3"), much like OPRO and EoH. This combines semantic proposals with QD's diversity pressure. pyribs' modular emitters make this a small integration.
- **Transfer to PCB — the TileGPT pattern for data.** Use QD plus a classical placer to generate a large, diverse, *labelled* placement dataset (descriptors as labels), then fine-tune an LLM or diffusion model conditioned on desired descriptors ("small, single-sided"). This addresses the data scarcity noted in Q2.
- **Transfer to PCB — WFC for repetitive tiled structures.** Keyboard matrices, LED arrays and multichannel boards suit tile-based constraint propagation; KiCad multichannel/design blocks are the native mechanism.
- **Transfer to PCB — Autodesk lesson.** Scoring metrics should come from stakeholders (assembly cost, testability or probe access, enclosure fit, EMI), and the human picks from a scored gallery. A KiCad plugin could show a 3×3 grid of thumbnails from the archive.

### Gaps
- QDax (JAX) features not retrieved.
- No QD application to PCB or VLSI placement found.
- TileGPT details come from a secondary review only.

## Q10. Most promising transplants, ranked by expected payoff vs effort

### Takeaway
The best near-term value comes from transplants that **keep the LLM on semantics and topology and hand geometry to proven solvers**, with fast automatic feedback.

### Cited Findings
Key evidence behind the ranking:
- Hybrid LLM poses plus differentiable relations beat pure-LLM and pure-constraint baselines. — [LayoutVLM](https://ai.stanford.edu/~sunfanyun/layoutvlm/)
- Imperative programs plus LLM-free program search were preferred 82% and 94% over declarative solvers. — [arXiv 2510.16147](https://arxiv.org/html/2510.16147v1)
- Training-free ranking of LLM samples matches trained SOTA. — [LayoutPrompter](https://proceedings.neurips.cc/paper_files/paper/2023/hash/88a129e44f25a571ae8b838057c46855-Abstract.html)
- VLM render critique and library learning help. — [SceneCraft](https://proceedings.mlr.press/v235/hu24g.html)
- A VLM proposing region constraints, plus evolution, gives SOTA macro placement. — [VeoPlace](https://icml.cc/virtual/2025/51511)
- LLM-evolved placement order cuts wirelength 14–34%. — [OrderPlace](https://tldr.takara.ai/p/2606.08904)
- LLM-evolved heuristics beat classic packing heuristics. — [FunSearch](https://github.com/google-deepmind/funsearch); [EoH](https://arxiv.org/html/2401.02051v3)
