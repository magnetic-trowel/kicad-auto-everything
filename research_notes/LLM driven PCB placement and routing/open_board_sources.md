# Open board sources for a KiCad placement/routing benchmark harness (as of 2026-10-21)

Scope: where to get real (and synthetic) PCB netlists, schematics and board layouts that can feed a harness that strips routing or placement from KiCad boards and re-scores with KiCad 10 `kicad-cli pcb drc`; licences verified at pinned commits; a vetted manifest at `bench/manifests/candidates.jsonl` (plus `netlist_candidates.jsonl`). Builds on, and does not repeat, `docs/topics/data/corpora-and-yield.md`, `licensing-tiers-and-contamination.md`, `verification/benchmarks.md`, `routing/benchmarks-and-datasets.md`, `routing/pcbworld.md`, `placement/benchmarks-and-metrics.md`.

Method note: every repository below was cloned at depth 1 with `--filter=blob:none` (trees only), boards and licence files were read with `git cat-file` at the recorded HEAD commit, and each `.kicad_pcb` was parsed by our own S-expression counter and re-checked by opening it in KiCad 10.0.7 (`pcbnew` Python module) and running `kicad-cli pcb drc --severity-all --format json` with the project's own `.kicad_pro`/`.kicad_dru` next to it. "DRC" numbers below are ours, measured on 2026-10-21 with KiCad 10.0.7, zones as saved (no refill). Scripts lived in the scratchpad, not the repo.

## Q1. Existing datasets and benchmarks: what is public and how to obtain it

### Takeaway
No public dataset ships redistributable, pinned, licence-verified *modern* KiCad boards except one: **punkfab/pcb-corpus** (235 KiCad 6–9 boards with repo+commit+path, own project rules, CC0 manifest). PCBWorld D3 is reproducible but not redistributed: it is rebuilt from **PCBench @ `dec3be75`** with a KiCad 9 conversion chain, and its board list is PCBench folder names, not upstream repo+commit. Freerouting now carries the PCBench boards with KiCad 10.0.2 DRC ground truth. OmniLayout/OmniRouting data is still not public.

### Cited Findings
- **PCBWorld does not ship boards.** `configs/datasets/d3.json` is "the ONE shipped dataset: the D3 real boards (677 of the 679 PCBench boards under `$PCBWORLD_DATA_ROOT/pcbench/exacad_sorted`)"; `tools/quickstart/prepare_pcbench.sh` "rebuilds them from the public PCBench clone" — [PCBWorld configs/datasets/README.md @1989a93](https://github.com/LGAI-Research/PCBWorld/blob/1989a9325796b73cca793a0c8f222dd1509256e8/configs/datasets/README.md)
- **PCBWorld rebuild chain:** PCBench `PCBs/<name>/processed.kicad_pcb` ("KiCad 5 file format, no project file") → `convert_v9.py` (pcbnew load+save to KiCad 9, `.kicad_pro` derived from legacy `(setup)`) → `drc_fix_v9.py` (severities to ignore, some rule floors to 0; boards that then pass DRC are the pool) → `make_guide.py` (per-net uniform-width guide board + `_unrouted` strip) → `sort_prefix.py` (order by pins, nets, components) → `make_dsn_orp.py`. "With the engine's own 9.0.8 build, 1 182 board folders convert and 679 pass the DRC filter — the paper's set exactly"; clone pinned at "`main` @ `dec3be75`"; ~4 GB disk, clone 1.2 GB — [pcbench_prep/README.md](https://github.com/LGAI-Research/PCBWorld/blob/1989a9325796b73cca793a0c8f222dd1509256e8/tools/datagen/pcbench_prep/README.md)
- **D3 splits:** CSV order is monotone in pins; rows [0,100) → easy (100), remaining with pins ≤ 100 → medium (287), pins > 100 → hard (292). Two boards are excluded (`0096_karabas-nano_wifi_revA`: 73 nets exceed the RL checkpoints' 64-slot cap; `0170_hackaday_esp-14…__autosave`: clearance 0), leaving 99/286/292 = 677. Test sets: easy.test = all 99; medium.test and hard.test = 10 two-layer boards each, one lower-median-pin board per quantile bin (hard drops top 10% pins first); `train` mirrors the full list "deliberately" and is never trained on — [d3_dataset/README.md](https://github.com/LGAI-Research/PCBWorld/blob/1989a9325796b73cca793a0c8f222dd1509256e8/experiments/kdd/d3_dataset/README.md), [configs/datasets/README.md](https://github.com/LGAI-Research/PCBWorld/blob/1989a9325796b73cca793a0c8f222dd1509256e8/configs/datasets/README.md)

### Inferences
- For PCBWorld comparability the harness should call PCBWorld's own `prepare_pcbench.sh` (needs KiCad 9.0.8 engine build) rather than reproduce D3 from our manifest; our `pcbworld-d3` rows are a licence-filtered pointer subset for non-comparative use.
- pcb-corpus is the best seed for a modern 2/4-layer tier: pinned, own rules, CC0 metadata; but its licences are GitHub-detected and need the README audit we did.
- Freerouting's KiCad 10.0.2 per-board DRC JSON is a free quality label for all PCBench boards, but under KiCad default rules only.

### Gaps
- PCBWorld's paper-exact guide boards are not downloadable; only the rebuild chain is.
- No upstream commit is recorded for any PCBench/D3 board; we did not attempt blob-hash matching against upstream history (feasible with `git log --all --find-object=<blob>` on tree-only clones).
- OmniLayout/OmniRouting: no release found as of 2026-10-21.

## Q2. Direct open-hardware KiCad projects with verified licences

### Takeaway
Modern (KiCad 7–10) complex boards with clean licences are concentrated in a few organisations: **Antmicro (Apache-2.0: Jetson/Kria carriers, DDR4/DDR5/LPDDR4 testers with 10–12 layers)**, **Great Scott Gadgets (CERN-OHL-P)**, **MNT (CERN-OHL-S)**, **Olimex (hardware licence in README: Apache-2.0, CERN-OHL-S or CERN-OHL-1.2)**, **azonenberg (BSD-3)**, plus KiCad's own CC BY-SA demos and Raspberry Pi's MIT minimal designs. Several famous projects are not usable: Altium (LimeSDR Mini, ODrive, SimpleFOC shield), non-commercial (Crazyflie CC BY-NC-SA, endgame trackball CC BY-NC), no hardware in repo (OpenMV boards, Watchy, PocketPD, gamebub), or no licence.

### Inferences
- GitHub's licence detector is wrong for at least three common OSHW patterns (dual hardware/code LICENSE.md, README-only hardware licence, per-directory hardware licence); any pipeline that trusts it (PCBench metadata, pcb-corpus, kicad-happy-derived lists) mislabels some boards.
- Antmicro alone provides most permissive 8–12-layer DDR/BGA/MIPI/PCIe boards; diversity at the top tier depends on reciprocal licences (MNT, Olimex, Marble, ButterStick, OrangeCrab).

### Gaps
- BeagleBoard (openbeagle.org), Framework laptop mainboards and Bitcraze Crazyflie 2.x are not KiCad-open; we did not find KiCad sources for OpenMV cameras.
- We did not check OSHWA certification ids for each board beyond OrangeCrab (README states OSHWA AU000015).

## Q3. Netlist-only and schematic-only sources

### Takeaway
For placement-from-scratch, the cheapest high-quality source is the **schematics of the manifest boards themselves** (most have a root `.kicad_sch`; `kicad-cli sch export netlist` gives the netlist and footprints already match KiCad libraries). Truly netlist-only public sets are small or footprint-less: BenchPCNP (Protel netlists, CC BY 4.0), Cypress Bookshelf (Apache-2.0), RL_PCB (MIT, tiny), atopile package sub-layouts (MIT), SKiDL/tscircuit generators (MIT).

### Cited Findings
- atopile/packages: MIT LICENSE, 157 package dirs, 1,795 `.ato` files and 422 `.kicad_pcb` sub-layouts (`layouts/default`, `layouts/usage`), each `ato.yaml` declaring `license: MIT` — [atopile/packages @38e6b64](https://github.com/atopile/packages/tree/38e6b64baece2ec1dcaffbfa1715763b06d3e597)
- SKiDL is MIT ("The MIT License (MIT) Copyright (c) 2016-2021, Dave Vandenbout") — [LICENSE @881a4d0](https://github.com/devbisme/skidl/blob/881a4d0f97ea0869e03501088245b8e21e4c2526/LICENSE); tscircuit is MIT — [LICENSE @6e6fd35](https://github.com/tscircuit/tscircuit/blob/6e6fd35c6c393639a84f589f170e831425a60756/LICENSE)
- BenchPCNP netlists are Protel/Protel2 with per-module sub-netlists (module labels such as Power, Crystal, ADC, Driver) — [Figshare](https://figshare.com/articles/dataset/BenchPCNP_Benchmark_Dataset_for_Printed_Circuit_Board_Netlist_Processing/30020125)
- KiCad demos include ~20 simulation schematics (no boards) under CC BY-SA 4.0 — [demos/simulation](https://gitlab.com/kicad/code/kicad/-/tree/b1d58a59a9a3da4d061ee3dc22ceba3d11812eb2/demos/simulation)
- Cypress Bookshelf small-11..20 have no KiCad twin (only small-1..10 have one) — [benchmarks/](https://github.com/NVlabs/Cypress/tree/743b07c4e33dc52a00584d55d2e67f38f70957f5/benchmarks)

### Inferences
- Simulation schematics and BenchPCNP lack footprints, so they need a footprint-assignment step before any placement task; they are better for module-recognition tasks.
- Generated designs (atopile, SKiDL, tscircuit) are contamination-resistant (novel netlists can be synthesised) but lack human placement references.

### Gaps
- No public corpus of "schematic + human placement, no routing" exists; strip-routing from manifest boards is the substitute.

## Q5. Practical fetch methods and pitfalls

### Takeaway
`git clone --filter=blob:none --no-checkout --depth 1` + `git cat-file -p <commit>:<path>` fetches only the board, project and licence blobs; verify `pcb_sha256`. Watch for Git LFS pointers, per-directory licences, multi-revision folders, legacy formats, non-GitHub hosts, and zip-only vendor designs.

### Cited Findings
- `git ls-tree -l` on a blobless partial clone lazily downloads every blob (it needs sizes); use `git ls-tree` without `-l` — observed while probing (a depth-1 Antmicro clone grew to 72 MB).
- KiCad 10.0.7 `kicad-cli pcb` subcommands: `drc, export, import, render, upgrade`; `import` takes non-KiCad PCB files, `upgrade` rewrites legacy formats — local `kicad-cli pcb --help`.
- kaebench's own `fetch` (raw URL for GitHub/GitLab, `git fetch --depth 1 <commit>` fallback otherwise) retrieved 31 sampled manifest rows, including the Forgejo-hosted MNT boards, GitLab KiCad demos with spaces in paths, and PCBench D3 pointers, all with matching sha256 — our run of [bench/src/kaebench/fetch.py](../../bench/src/kaebench/fetch.py).
- PCBWorld warns that stock `kicad-cli pcb drc` "stops reporting a violation type after 199 hits (clearance: 499)" — [pcbench_prep/README.md](https://github.com/LGAI-Research/PCBWorld/blob/1989a9325796b73cca793a0c8f222dd1509256e8/tools/datagen/pcbench_prep/README.md)
- Freerouting: DSN export only via `pcbnew.ExportSpecctraDSN` in KiCad 10; SES re-import unreliable headless on 10.0.2; DSN omits copper-to-edge clearance — [scripts/pcbench/README.md](https://github.com/freerouting/freerouting/blob/c4755a8874719dea76110860096776c4a9210994/scripts/pcbench/README.md)
- pcb-corpus: "A router that reads the board file directly will treat a stale zone fill as copper in its way… refill after routing, before DRC" — [README](https://github.com/punkfab/pcb-corpus/blob/1e999b4eefd5fdfcc90dc376d2882390245a8e0d/README.md)

### Inferences
- Submodules (e.g. latentred, dumptruck, orangecrab, eurorack-pmod) usually hold symbol/footprint libraries; KiCad boards embed footprints, so DRC and routing do not need them, but `lib_footprint_issues` warnings appear.
- Non-GitHub sources (source.mnt.re, gitlab.com, Raspberry Pi zips) need host-agnostic fetchers; zips have no commit, so pin by sha256 only.

### Gaps
- We did not test `kicad-cli pcb upgrade` round-trips on every legacy row.
