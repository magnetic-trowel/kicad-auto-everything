## What the runs changed in the gate

Each found on these boards and fixed in its own commit before the tables above:
1. Taut nets planned against each other conflict when only some are reverted: entries of one pass within clearance of each other's removed copper are merged.
2. Depth-first ddmin spent the budget halving taut and never tried power copper: breadth first.
3. Identity by position bucket read pre-existing violations on rewritten tracks, and a via's other partner pad, as new (cm4: 58 of 61 changes reverted at unchanged counts): matching by item coverage at any position, then by a shared item nearby.
4. A check at KiCad's error limit (199) reports a subset chosen by item order: judged by count; the noise run uses the output's item order.
5. Unnamed violations (starved thermals name their pad) were attributed only when nothing else was named.
6. Attribution reverts neighbourhoods: re-admission, clear-of-culprits first, failing batches split by what KiCad names, else by distance, entries blocked by a dependency retried after it is admitted.
7. A revert takes what built on it: a re-plan round runs the later stages again on the gated board (second gate, input report reused).
8. Noisy counts (magtag 24/25): an output above the input is read again, and the input sampled up to 4 times.
