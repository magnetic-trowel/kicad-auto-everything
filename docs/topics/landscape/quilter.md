# Commercial: Quilter (what it discloses)

**TL;DR**
- **Approach:** "Reinforcement learning + classical solvers + computational geometry". Placement and routing are one coupled search. Training is on **synthetic, physics-scored problems only**. Output is "dozens to hundreds of ranked candidates", numbered **X.Y** (placement X × router Y) [V].
- **Circuit Comprehension:** deterministic heuristics detect bypass caps, diff pairs, power nets, crystals and switching converters, which the engineer confirms. **8 Physics Rule Checks** (PRCs) score candidates. Ranking is **lexicographic** [P/V].
- **Honest limits:** "can't typically design or optimize boards as well as skilled humans". Recommended envelope: <5,000 pins, ≤20% pin density, <6 GHz, ≤48 V, ≤10 A. Through-vias only (2026-05-31) [V].
- **Project Speedrun** (843 parts, 8-layer HDI, booted first time) took 38.5 h of human work against 428 h quoted. But the **SOM placement was human-fixed and BGA fanout partly hand-routed** [V].
- **No public API and no patents** [P].

## Key facts

### Architecture and data
- "RL navigates the combinatorial search, but the candidates it proposes are checked against deterministic constraints, rules, and solver-backed calculations … differential-pair spacing should be derived from the stackup and impedance target, not guessed by a neural network" [V] ([blog](https://www.quilter.ai/blog/pcb-autorouter-was-the-right-idea)).
- **Data:** "Quilter is never trained on human-designed boards … built entirely from synthetic data generated by simulation" ([technology](https://www.quilter.ai/product/technology)). Free-tier designs "generate synthetic training puzzles"; paid designs are "never used for direct or indirect training" [V].
- **Engineer Fayaz Rahman:** "Router is very sequential … we can't do some sort of backtracking … The order and the constraints is probably the most difficult thing" [V] ([LLM post, 2026-09-08](https://www.quilter.ai/blog/llm-pcb-layout-gpt-6-astra)).
- **Speed history:** at the Feb 2024 launch a job took 2–3 h to the first candidate and 4–8 h in total, with routing ~70% of job time. The local router moved from Python to C++ (6.7×) and global routing was rebuilt (4×), giving routing 27× and jobs 9.4× faster. A job "explores 50+ unique designs and produces 20 DRC-free, 100% complete candidates — all in less than an hour" [V] ([2024-07-01](https://www.quilter.ai/blog/jobs-under-1hr)).
- **Stackups:** before 2026-03-26 a job tried many stackups (standard 2/4/6-layer from OSH Park, JLCPCB, MacroFab); now it uses one. Diff pairs came from a 2D quasi-static solver; since 2026-06-30 any target is solved with Simbeor [V].
- **Self-description:** "a design agent, not a 'copilot'". It does no silkscreen placement, no datasheet review and no schematic-logic checking [V].

### Ranking ("Recommended" sort, lexicographic)
1. Min DRC violations, then max routing completion.
2. Max passing **priority** PRCs (power nets, diff pairs, single-ended impedance).
3. Most conservative fab rules (max min-trace-width, then clearance, drill, via).
4. Fewest layers.
5. Other PRCs.
6. Shortest traces.

Source: [docs: Sorting](https://docs.quilter.ai/candidate-review/sorting) [P].

### Circuit Comprehension heuristics (auto, then confirmed)
| Constraint | Detection and behaviour |
|---|---|
| Bypass caps | "Connected between a component and ground". Parent pin priority: (1) explicit wire, (2) voltage-type pin names, (3) equal split across same-name pins. Smaller capacitance placed closer; one cap may serve several pins |
| Crystals | Refdes starts with X or Y and both pins go to one parent. Load-limiting resistors not supported |
| Switching converters | Refdes U* whose output connects to an L* inductor; the three passives placed "as closely as possible" |
| Power nets | Voltage-like names or a "Power" class. Default current 200 mA (<3 V) or 500 mA (>3 V). Per-layer widths from IPC-2221 heating |
| Diff pairs | From net names (`_P`/`_N`). Need differential impedance, single-ended impedance and carrier frequency. Multi-receiver pairs not routed; always microstrip |
| Timing-sensitive | "In internal testing and not yet publicly available" |
| Custom Component Proximity | Child within N mm of a parent pin (sense resistor, snubber); placement plus PRC (2026-05-01) |
| Unspecified | "Routed as generic signals" |

Sources: [docs](https://docs.quilter.ai/physics-constraints/bypass-capacitors) (constraint pages), [Compiling (Part 2/6)](https://www.quilter.ai/blog/compiling-an-ai-designed-computer) ("replaces [the layout-kickoff] meeting") [P].

### The 8 Physics Rule Checks (exact list, corrected by VK)
| PRC | Definition and example threshold |
|---|---|
| Ground Plane Overlap | Plane on the layer below overlaps both traces everywhere except 2×clearance at each end (boolean) |
| Overheated Length | Segments with analytic temperature rise >20 °C; example pass 0–10% of net length |
| Pin Distance | Closest pin-edge distance; example 0–1 cm |
| Layer Switch Count | Vias between a bypass cap and its pin; example 0–1 |
| Length Mismatch | Example 0–1 cm |
| Uncoupled Spacing | Spacing more than 10% off the solver nominal; example 0–1 cm uncoupled |
| Trace Path Length | Example 0–1 cm |
| Invalid Width Span | Width outside ±10% of nominal; percentage plus a fallback length threshold |

- **Mapping:** power → Overheated Length; single-ended impedance → Invalid Width Span and Ground Plane Overlap; diff pairs → Ground Plane Overlap, Uncoupled Spacing and Length Mismatch; caps, crystals and switchers → Pin Distance, Trace Path Length, Layer Switch Count and Ground Plane Overlap.
- **Planned:** top-plane ground pour, neck-downs, trace proximity.
- PRCs launched 2024-11-18 as per-constraint "unit tests", meant to become "a critical feedback system that drives Quilter's ongoing learning" [P] ([PRC overview](https://docs.quilter.ai/physics-rule-checks-prcs/overview)).

### Floorplan controls and inputs
- **Control levels**, most Quilter freedom to least:
  1. Schematic clustering.
  2. Anchoring (pre-place one member and the group "sticks").
  3. Off-board regions (grouping only, either side); off-board regions plus an anchor ("our current favorite"); on-board regions (hard rooms, multipolygon allowed).
  4. Manual placement (anything inside the outline is locked).
  - Leftover vias block placement [P] ([placement guide](https://docs.quilter.ai/guides/placement-guide)).
- **Inputs:**
  - One closed outline (KiCad Edge.Cuts or Altium Mechanical 1), footprints, and a netlist matching the schematic.
  - Ground and power layers must be named ground/gnd and power/pwr.
  - Pre-placed parts and pre-routed traces are kept; pre-place connectors.
  - Results come back in the same native format.
  - CAD support: Altium, KiCad, Allegro/OrCAD, Xpedition; Zuken CR-8000 and EasyEDA as "other" [P].

### Project Speedrun (Dec 2025)
- **Board:** i.MX 8M Mini; 843 components; 5,141 pins; SOM plus baseboard; 8-layer HDI; built by Sierra Circuits.
- **Human time:** baseboard 12 h plus SOM 26.5 h = **38.5 h**, against 238 h + 190 h = 428 h quoted. "98%" was claimed autonomous (corrected per PI) [V] ([Speedrun](https://www.quilter.ai/project-speedrun)).
- **Baseboard:** ~27 h of compute; ~500 parts placed; ~2,000 pins routed; 98.4% complete at 3.5 mil. A 99% candidate at 3 mil was rejected for manufacturability.
- **SOM:** "We chose not to use Quilter for component placement on the SOM … fixed the placement based on the original design", plus "a partial human fanout for the BGAs". Early runs reached 60–70% with no length matching; the final run was 98.7% at 2 mil, a 15 h job.
- **Cleanup:** enlarging polygons; length tuning, because the engine "did not yet account for via delay"; widening high-current nets; moving L102.
- **Bring-up:** LPDDR4 trained at 3 GT/s; 10 + 10 boards all ran.
- **Fab review:** Sierra raised 58 DFM/DFA findings, 48 of them documentation, library, BOM or supply-chain items. Impedance came back 62 Ω versus a 50 Ω target (±30% accepted) and 92 Ω versus 100 Ω (±20%) [V] ([Part 6](https://www.quilter.ai/blog/ai-designed-motherboard-dfm-dfa-lessons)).
- **Reception:** HN top comment "Designed with AI, not by AI". Quilter's own framing: "keep the schematic identical and prove out only the layout portion"; parallel seeded runs [P].

### Business and deployment
- **Pricing:** "Pay per Project. Not per Seat", set by unrouted pins at upload, with unlimited iterations within 10% BOM change and parallel jobs. No public price.
- **Deployment:** AWS (SOC 2 Type 2), or self-hosted Helm on Kubernetes with NVIDIA GPUs (≥16 GB VRAM); air-gapped possible.
- **Free tier:** for teams with fewer than 10 people and under $50K revenue [P] ([pricing](https://www.quilter.ai/pricing); [FAQ](https://docs.quilter.ai/about-quilter/faq.md)).
- **No public API**; enterprise "custom integrations" only [P].
- **Company:** founded 2019 by Sergiy Nesterenko (ex-SpaceX). $10M Series A (Feb 2024) [S]; $25M Series B led by Index (2025-10-07) [P].
- **Patents:** USPTO queries (2026-10-20) found only Handi Quilter and Quilter Labs. **No Quilter AI-layout patents** [P].

## Recommendations for our system
- **Copy the pattern** propose → construct (correct-by-construction physics) → verify (PRCs) → rank lexicographically, with a placement × router candidate matrix [I].
- **Reproduce the comprehension heuristics deterministically** and let the LLM add recall (datasheets, interfaces, current estimates), keeping the human confirmation step [I].
- **Re-express the PRC definitions and thresholds** in our own words as CC0 rule records with citations, not copied text ([../licensing/data-rulepacks-weights.md](../licensing/data-rulepacks-weights.md)) [I].
- **Target what Quilter leaves open:** timing and DDR, via-delay-aware tuning, >20% density [I].
